# ddm501-assignment2-ml-pipeline

Training pipeline for a **CNC machine-failure risk model**, built for DDM501 Individual
Assignment 2 (ML Pipeline Design & MLOps Analysis). It continues the system design of
Assignment 1: a mid-size machining plant wants to inspect the riskiest 5 % of production
cycles so that planned interventions replace unplanned failure stops. The public
[AI4I 2020 Predictive Maintenance dataset](https://archive.ics.uci.edu/dataset/601) (CC BY 4.0)
stands in for the plant's history.

The written report is `DDM501_Assignment2_[StudentID]_[Name].pdf` (source: `report/report.md`).

## What is in here

| Path | Content |
|---|---|
| `src/pm_pipeline/` | Python package: one module per stage (`ingest`, `validate`, `preprocess`, `features`, `train`, `evaluate`, `register`, `predict`), plus `config`, `tracking`, `results`, `cli` |
| `configs/pipeline.yaml` | Every tunable value (paths, split, alert budget, cost model, MLflow, gates). Override any key with `PM_<SECTION>__<KEY>` |
| `configs/experiments.yaml` | The 14-configuration experiment matrix |
| `dags/pm_training_dag.py` | Airflow 2.8 TaskFlow DAG (weekly, dynamic task mapping, retries, failure/SLA callbacks) |
| `tests/` | 33 pytest tests (90 % line coverage) |
| `scripts/make_figures.py` | Report figures and tables, read straight from MLflow |
| `Dockerfile`, `requirements.lock` | Reproducible runtime; `docker/airflow.Dockerfile` for running the DAG |
| `reports/` | Generated results table, Airflow parse output and `dags test` log |
| `data/raw/ai4i2020.csv` | The dataset, unchanged, with attribution and sha256 in `data/README.md` |

## Quick start

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"

.venv/bin/pm-pipeline validate            # ingest (sha256-pinned) + data quality gate
.venv/bin/pm-pipeline all                 # 14 MLflow runs -> results table -> register best model
.venv/bin/pm-pipeline promote --version 2 # human promotion of a challenger (rollback = same command)
.venv/bin/mlflow ui --backend-store-uri sqlite:///mlflow.db

.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/pytest -q
```

A full run of the matrix takes about 2.5 minutes on a laptop. MLflow state (`mlflow.db`,
`mlartifacts/`) and working files (`data/interim/`) are git-ignored and regenerated by the
commands above.

## Results (5-fold CV on the first 8,000 cycles; holdout = last 2,000 cycles)

| Run | CV recall at 5 % alert budget [95 % CI] | CV PR-AUC | Holdout recall at 5 % |
|---|---|---|---|
| E07 random forest + physics features + class weights | 0.890 [0.85, 0.92] | 0.901 | 0.795 |
| E08 random forest + physics features + undersampling | 0.890 [0.85, 0.92] | 0.875 | 0.821 |
| **E11 hist. gradient boosting + physics features + class weights (selected)** | **0.887 [0.85, 0.92]** | **0.907** | **0.769** |
| E12 LightGBM + physics features | 0.887 [0.85, 0.92] | 0.907 | 0.821 |
| E13 LightGBM + physics features + oversampling | 0.883 [0.85, 0.91] | 0.907 | 0.821 |
| E02 logistic regression (ML baseline) | 0.550 [0.50, 0.60] | 0.452 | 0.641 |
| E01 tool-wear rule (current practice) | 0.220 [0.18, 0.27] | 0.119 | 0.641 |

Full table: `reports/experiment_results.md`. Selection rule, gates and the reasoning are in the
report (section 2).

## Running the DAG

The DAG imports the package inside its tasks, so it parses in a plain Airflow image:

```bash
docker run --rm --entrypoint "" -v "$PWD":/opt/airflow/project:ro apache/airflow:2.8.4-python3.11 \
  python -c "from airflow.models import DagBag; print(DagBag('/opt/airflow/project/dags', include_examples=False).import_errors)"
```

For an end-to-end run, build `docker/airflow.Dockerfile` and use `airflow dags test
pm_failure_risk_training <date>`; the output of such a run is in `reports/airflow_dags_test.log`.

## Rebuilding the report

`./report/build.sh` renders the Mermaid diagrams (`report/diagrams/*.mmd` to SVG and PNG), converts
`report/report.md` to HTML with pandoc and prints it to PDF with headless Chrome.
